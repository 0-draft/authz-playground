# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

A browser-only teaching site (no backend) that feeds the same authorization requirements to 5 engines, Cedar / OPA (Rego) / Casbin / ReBAC (Zanzibar) / ReBAC + Conditions (OpenFGA-style conditional tuples), and shows where their answers split. The remote is `0-draft/authz-playground`; push to main deploys to GitHub Pages. The UI and code comments are in English; display strings are in two languages, en/ja.

## Layout (big picture)

- `src/core/scenario.ts`: the engine-neutral scenario. Requirements R1 to R4, the 4 stages that add them cumulatively (`STEPS`), and enumeration of every request (`enumerateRequests`).
- `src/core/engine.ts`: the `PolicyEngine` interface. Each engine has `project()` (projects into its native representation and returns the source shown in the UI plus expressibility `native`/`awkward`/`impossible`) and `prepare()` (builds the evaluator).
- `src/engines/*`: the adapters. Cedar uses `@cedar-policy/cedar-wasm`, Casbin uses the TS implementation directly, the two ReBAC engines are teaching reimplementations in `rebac.ts` (not OpenFGA), and Rego calls OPA itself, built to `js/wasm` from `wasm/rego/main.go`, through `regoRuntime.ts`.
- `src/core/diff.ts`: the differential harness. Runs every request through every engine and tallies disagreements.
- `src/core/oracle.ts`: an independent ground-truth function written directly from the requirement text. Test-only, and deliberately kept outside `src/engines` (so it does not become a fifth projection).
- `src/App.tsx`: the main screen. Engines are listed in `ALL_ENGINES`. Rego joins the comparison only after the wasm has finished loading (`enginesFor(regoReady)`).
- `src/i18n.ts`: display strings are `L = { en, ja }`, with both languages required. Comments inside the source generated by `project()` are also localized by `lang`.

## Invariants (do not break)

- **The differential harness is the project's claim itself.** `src/core/diff.test.ts` pins: "the 4 engines that handle context agree on every request at every stage", "only classic ReBAC diverges, and only on edits outside business hours", "every engine agrees with the oracle", and "the business-hours boundaries 08/09/17/18 are checked directly". Do not fix a projection by bending the test to match. When a test fails, first determine whether it is a projection bug or a real semantic difference.
- **Keep expressibility declarations (`support`) consistent with measured behavior.** The design makes tests fail when declaration and behavior drift, so do not settle it by hand-editing the table.
- **Do not leave a guard in a state where deleting it still passes the tests.** Past fixes removed cases where something was only verified across a seam and stayed green with the guard deleted (`614375c` / `c8cf10a`). Write tests through the real wiring such as `decide()` and `runDifferential`. Assert state, not wording (`72da6e9`).
- **The Rego wasm compiles arbitrary Rego pasted by the user**, so `main.go` removes the `http.` / `net.` / `opa.runtime` builtins from capabilities. `http.send` deadlocks the single goroutine and the runtime is dead from then on. Do not relax the handling of builtins.
- **Casbin role definitions are numbered from `g`.** Declaring only `g2` and skipping `g` means the grouping is not registered (upstream behavior, see README).
- Long loops yield per request with `yieldToBrowser()` so they do not freeze the browser (yielding only between engines was not enough).

## Pitfalls

- **`public/rego.wasm` (about 40 MB) and `public/wasm_exec.js` are generated files that are not committed.** Without them, `npm test` fails in the `vitest.setup.ts` preload. `npm run build` succeeds without them and produces a 4-engine site without Rego, so CI checks the size of `dist/rego.wasm`.
- vitest runs on Node, so Cedar is aliased to `@cedar-policy/cedar-wasm/nodejs`, and the Rego wasm is preloaded in `vitest.setup.ts` and attached to `globalThis.regoEval`. This is separate from the browser loading path (`regoRuntime.ts`).
- Casbin references Node's `Buffer` in the browser, so `src/polyfill.ts` must load before `main.tsx`.
- Prettier (`format:check`) covers all of `.`, including Markdown. After writing a `.md`, also pass `npx prettier --check`.
- Deploy is a later job in the same workflow as CI. When it was a separate workflow, a commit with a failing harness reached production.
- `claude-review.yml` only reviews PRs and is not a gate. Changes to it are not reviewed until merged.

## Common commands

```bash
npm install
npm run build:wasm     # needs Go. Builds wasm/rego to js/wasm and outputs to public/
npm run dev

# Verification in the same order as CI
npm run format:check
npm run lint
npm run typecheck
npm test               # differential harness
npm run build

# Go side (equivalent to the CI gofmt job)
cd wasm/rego && gofmt -l . && GOOS=js GOARCH=wasm go vet ./...
```

`wasm/rego/go.mod` is authoritative for the Go version (CI follows it via `go-version-file`). dependabot opens PRs against `/wasm/rego` for OPA updates.

## PRs to upstream OPA

Work in this repo sometimes leads to PRs against `open-policy-agent/opa`. OPA's `.github/PULL_REQUEST_TEMPLATE.md` requires the PR body to be written by a human (AI may only write code).
